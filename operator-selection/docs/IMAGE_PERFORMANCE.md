# 图片加载与缓存

原素材保留在 assets/tokens、assets/icons 和 assets/operators。页面通过 src/config.js 中的统一映射加载 assets/optimized 中的轻量文件，CSV 的原素材文件名无需修改。

- 头像保留 SVG，无损复制为带内容指纹的文件名。
- 骰子、血量、破坏图标缩小到最长边 128 像素，再编码为无损 WebP。缩放后的像素保持透明度，不改变配色或绘制内容。
- 干员面板最长边 2560 像素，WebP 质量 86，打开时才下载。
- 原图和轻量图的 SHA-256 记录在 src/asset-manifest.js，测试会发现源素材已更换但轻量图未更新的情况。

## 更新素材

1. 替换原素材；修改 CSV 时先运行 `node scripts/build-operators.mjs`。
2. 安装开发依赖后运行 `npm run optimize-assets`。生成器会更新轻量图、资源映射、缓存清单和页面引用版本。
3. 运行 `npm test`，连同生成文件一起发布。

生成器可使用项目安装的 sharp，也兼容桌面工具附带的 Node 运行时。旧指纹文件暂不自动删除，以便已打开的旧页面继续加载原版本资源。

## 设备缓存

Service Worker 仅控制 operator-selection 路径，按白名单缓存带内容指纹的图片，不缓存 HTML、脚本、CSV 或游戏数据。头像、属性图标及阵营图标在页面加载完成后的空闲时预热，最多三个请求并发；省流量模式和 2G 网络不主动预热。

后续访问缓存优先，同一图片不重复下载。修改后的图片使用新指纹，自动下载新版；没有变化的图片继续复用缓存。Worker 激活时清理清单中已失效的缓存条目。

面板按需缓存，最多 24 张，超出时删除最早缓存的面板。图片下载失败、错误页、存储空间不足或浏览器禁止缓存均不会把错误内容作为图片保存。缓存不可用时使用普通网络加载。

首次页面交互会尝试申请持久化存储，浏览器可以拒绝。浏览器清理、用户清理网站数据或无痕会话仍可能移除缓存，因此不保证永久保存。未缓存的页面本身不支持离线打开；已经加载的页面可以离线使用已缓存的图片。

## 验证

`npm test` 覆盖缓存复用、Worker 重启、素材版本更新、非图片请求不拦截、面板数量上限、存储失败回退、失败响应不缓存及素材源一致性。

`node scripts/verify-operator-images.mjs <截图目录>` 使用 Playwright 和已安装的 Edge 开一个隔离浏览器，模拟 GitHub Pages 的 /los/ 子路径。测试服务器禁用普通 HTTP 缓存，验证第二次访问图片网络请求为零、离线切换阵营、离线读取骰子与已打开面板，以及手机端布局。

实测：实际使用的 11 张属性图从 6,137,502 字节降至 118,430 字节；87 张面板从 403,148,749 字节降至 41,262,842 字节。72 个不同头像和 5 个 UI 图标保留原文件内容。全部常用图片约 460 KB，面板不计入首次预热。
